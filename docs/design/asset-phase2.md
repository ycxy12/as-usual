# 日常集：第二阶段「物品」设计

状态：用户已确认进入实现，2026-09-18。

## 范围

「物品」Tab 包含个人物品与衣柜两个独立模块，共用现有微信登录、图片上传和视觉样式。发现、我的仍为占位页。业务主数据保存在服务端 MySQL，前端本地仅缓存会话。

## 数据与接口

- 个人物品：名称、图片、分类、品牌、型号、购买日期、购买价格、当前估值、保修截止、状态、存放位置、标签、备注。分类为数码产品、摄影器材、家电、家具、工具、收藏品、其他。
- 衣柜：名称、图片、分类、品牌、颜色、尺码、季节、购买日期、购买价格、穿着次数、最近穿着日期、状态、标签。分类为上衣、裤装、外套、鞋、包、配饰。
- 服务端生成 ID、创建/更新时间；每条记录与图片都按当前用户隔离。标签分别在关系表存储，单张图片通过现有 image_asset 与一条记录关联。
- `/api/v1/items`、`/api/v1/wardrobe` 提供分页、关键词及分类/状态筛选、详情、新增、修改、删除、统计；`/api/v1/wardrobe/{id}/wear` 原子增加穿着次数并更新最近穿着日期。
- 删除物品或衣物时清除其图片元数据和文件；更新图片时验证所有者和未被其他记录占用。旧碎片接口也检查跨模块图片占用。

## 统计口径

- 物品详情：持有天数为购买日起至今天的自然日差（购买当天为 1 天）；折旧金额为 `max(购买价－当前估值, 0)`；使用成本为折旧金额除以持有天数（元/天）。未填购买日期或价格时显示空值。保修截止日含当天有效。
- 物品总览：总数、购买总价、当前估值及分类数量。
- 衣柜总览：总数、分类数量、长期未穿数量与穿着排行。长期未穿定义为最近一次穿着距今天至少 90 天；未穿过的衣物从购买日计，未填购买日的不计入。单次穿着成本为购买价除以穿着次数，零次时显示空值。

## 页面

物品 Tab 首页给出两个模块的入口和摘要；各模块列表支持筛选、分页和空状态。表单支持添加、编辑、图片、标签；详情展示字段和统计，衣柜详情支持「今天穿了」操作。删除二次确认，离开未保存表单给出提示。

## 验收

1. 两个用户数据及图片互相隔离，跨模块图片不能重用。
2. 新增、编辑、删除后列表和统计更新；筛选与分页正常。
3. 物品折旧/持有天数、衣柜 90 天规则和单次穿着成本正确。
4. 穿着操作重复调用按次数累计；删除后图片不可读取。
5. Maven 测试、格式检查、TypeScript 检查与页面结构检查通过。真实微信登录和真机展示需 AppID、AppSecret 与可用后端环境。
