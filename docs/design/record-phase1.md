# 日常集：第一阶段「记录」当前设计

状态：已由用户确认「微信原生小程序 + 后端数据库」方向，2026-09-18。

## 技术边界

- 小程序：微信原生 TypeScript、WXML、WXSS、微信开发者工具；不引入跨端 UI 框架。四个原生 Tab 固定为记录、物品、发现、我的，后三个仅占位。
- 服务端：Java 17、Spring Boot 3.5、Maven、单体应用、MySQL。首期以 Spring JDBC 为数据访问层、Flyway 管理数据库版本；按业务模型分包，不拆微服务。
- 数据源：四个记录模块的主数据写入服务端。前端页面调用各模块 Service，Service 调用统一 HTTP 客户端；本地仅保存会话，不保存权威业务数据。
- 身份：`wx.login` 换取一次性 code；服务端用微信 `jscode2session` 获取 openid，向小程序签发随机 bearer token。业务请求一律按当前 openid/用户 ID 隔离。无账号 UI。
- 图片：碎片图片经服务端上传，图片元数据关联所属用户。展示时小程序用认证请求下载为临时文件，避免公开个人照片。

## 业务模型

核心记录均有 `id`、`createdAt`、`updatedAt`、`ownerId`。客户端仅提交业务字段；服务器生成 ID、时间和 ownerId。

| 模块 | 实体 | 要点 |
|---|---|---|
| 每日碎片 | Fragment、FragmentImage、FragmentTag | 时间、正文、多标签、多图片；搜索、日期及标签筛选；分页 |
| 车辆 | VehicleRecord | 费用类型、金额、可选里程/数量/单价/地点；月年累计、分类、里程统计 |
| 居住 | HousingRecord | 分类、金额、账期、日期；月年累计、分类及月度统计 |
| 人情 | Contact、GiftRecord | 联系人一对多往来；送出/收到、现金/礼物、金额、礼物名称、事件 |

金额使用数据库 `DECIMAL(12,2)`、Java `BigDecimal`，前端展示人民币。业务发生时间采用 `YYYY-MM-DDTHH:mm:ss` 本地日历时间字符串，创建与更新时间为服务端时间戳。删除均需二次确认；联系人删除时其往来记录同时删除。
居住费用的月度统计按所属账期计算；车辆每公里成本按首末两次已记录里程之间的费用与里程差计算。

## API 范围

所有业务接口位于 `/api/v1`。登录 `/auth/wechat`；碎片 `/fragments`；车辆 `/vehicles`；居住 `/housing`；联系人 `/contacts`，往来 `/contacts/{contactId}/gifts`；图片 `/images`。图片上传后先作为当前用户的临时资源，保存业务数据时完成关联；`DELETE /images/{id}` 只允许删除本人尚未关联的图片。客户端在替换、移除或放弃表单时主动清理，服务端在后续上传时补充清理超过 24 小时的未关联图片。列表支持分页，统计由服务端按用户数据计算。错误统一返回明确消息；未授权返回 401。

## 页面与交互

记录 Tab 首页聚合今日碎片、近期记录、本月车辆与居住成本、最近人情往来。每日碎片有列表、详情、新增、编辑、删除、搜索/标签/日期筛选。车辆、居住各有列表/统计与动态表单。人情有联系人列表、联系人详情、联系人表单及往来表单。空状态、保存 Toast、未保存离开提示、分页和安全区适用于各页面。

## 验收重点

1. 两个微信用户的数据不能互相读取或修改；伪造 ownerId 无效。
2. 新增、编辑、删除后重新进入页面仍可见正确状态；删除需确认。
3. 列表筛选和分页、金额与日期显示、四类费用统计符合数据。
4. 图片上传后重新进入详情可显示；无权用户不能下载。
5. 微信开发者工具编译、TypeScript 检查、后端构建和服务端定向测试通过。

## 本阶段约束

运行真实微信登录需要用户自己的小程序 AppID 和 AppSecret；服务端从环境变量读取密钥，不写入仓库。生产运行需配置 HTTPS 合法域名及 MySQL。物品、发现、我的的业务页面不在此阶段。
